# 体系设计：从领域到可执行大纲

目标：把「我想学 X」变成一个带依赖关系、带验收标准、带时间预算的模块图，且每块小到一次能学完。

## 一、先定成功判据，再拆模块

拆模块前必须能填空：

> 学完之后，我能在 ______ 场景下，独立完成 ______，且达到 ______ 水平。

填不出这句，说明目标还没定，回 `MISSION.md` 继续问。**不要用「了解」「熟悉」这类词当判据**，它们不可验收。

判据分三类，写法不同：

| 类型 | 判据写法 | 例 |
|---|---|---|
| 知识型 | 能解释 X 与 Y 的区别并给出反例 | 说清「相关」与「因果」的区别并各举一例 |
| 技能型 | 能在 N 分钟内独立完成 X | 15 分钟内手写一个带缓存的 LRU |
| 产出型 | 能交付一份可被他人评审的 X | 交一份 3 页的竞品分析，含数据来源 |

## 二、模块拆分规则

1. **3-12 个模块，推荐 5-12**。少于 3 说明拆得太粗；3-4 允许（范围小的主题），但要在 MISSION 里写明是单点目标；多于 12 说明目标太泛，先砍范围。
2. **一个模块 = 一次能学完的量**，时间预算 1.5-3 小时。超了就拆。
3. **模块必须有一个产出物**，不是「学完第 3 章」。产出物可以是：一张对比表、一段可运行代码、一份 5 句总结、一道变式题、一次口头讲解录音。
4. **模块标题用动词短语**，不用名词。「能看懂递归」优于「递归」。
5. **每个模块写清「验收」**：用什么证据说明这个模块过了。验收必须是可观测行为。

## 三、用教材目录做覆盖基准

不要凭印象列模块。先拿基准，再拆：

1. 取 **2 个独立教材版本的目录** + **1 份课程标准/考试大纲**（没有课标就再找一个版本）。
2. 三份取**并集**，作为模块候选池。求并集，不求交集——交集会漏掉只有一家讲的必要内容。
3. 并集里的条目归并成 3-12 个模块（推荐 5-12），每个模块写 `textbook_ref` 标出它对应哪几章。
4. 做**差集**：基准里有、你的大纲里没有的条目，逐个决定「补模块」或「写进 not_covered 并说明理由」。

差集是防「假全面」的唯一硬手段。不做差集，大纲就只是模型印象的排列。

快变领域（无教材或教材已过时）用官方文档的目录结构替代：文档的章节目录就是该领域的当前骨架。

## 四、前置依赖（DAG）

画法：

1. 先列全部模块，不排序。
2. 对每个模块问三句：它假设我已经会什么？去掉哪个模块会让它无法理解？它支撑后面的哪几个模块？
3. 只保留**硬前置**。软前置（「学了更好」）不进 `prereq`，写进 `nice_to_have`。
4. 检查三件事：
   - 无环（A 依赖 B、B 依赖 A → 合并或拆开）
   - 有唯一入口（至少一个模块 `prereq: []`）
   - 没有孤立节点（每个模块都通向某个产出物）

硬前置判定标准：**缺了它，这个模块的课听不懂，不是听得吃力，是听不懂。** 拿不准就按软前置处理。

### 每条前置必须写依据

`why_prereq` 不能空。写一句：「缺了 M01 的 ___，你会卡在 ___ 这一步」。写不出这句话，说明它不是硬前置 → 移到 `nice_to_have`。

这条是为了让用户在陌生领域也能审计 DAG。用户看不出「标题像不像」，但能判断「我是不是真的会卡在这一步」。

### M01 完成后强制复审

学完第一模块才有判断力，此时必须回来问一次：

1. M01 暴露出的实际难度，与原估计差多少？
2. 后面的 `why_prereq` 现在还成立吗？
3. 有没有模块该合并、该拆、该删？

复审结果写进 `syllabus.yaml` 并在 `learning-records/` 记一笔。宁可多一轮，不要带着错 DAG 走完 5 个模块。

### 前置未满足时

进模块前查 `mastery.md`：`prereq` 里每个模块 `core` 列表的概念必须 ≥ L3（没写 `core` 则取 `concepts` 前两个）。

未达时给三个选项，让用户选，不要自己决定：

1. 补前置（推荐，给出补哪几个概念、约几小时）
2. 降级目标（砍掉依赖该前置的模块，改 MISSION）
3. 硬上（记录到 `learning-records/`，标注风险）

## 五、时间预算

```yaml
horizon_weeks: 6
weekly_hours: 3
```

- 总预算 = `horizon_weeks × weekly_hours`。各模块 `budget_hours` 之和不得超过总预算的 80%，留 20% 给复习与返工。
- 复习成本单独算：每个模块学完后，复习会持续占用 10-15 分钟/天。别把复习时间算进学习时间。
- 预算超了，先砍模块，不要压缩单模块时长——压到 1 小时以下的模块学不透。

## 六、拆不出体系时的四个退路

| 症状 | 处理 |
|---|---|
| 领域太大（「学编程」） | 换成一个可交付目标（「三个月内独立上线一个带登录的网站」），按目标反推 |
| 没有公认结构（新兴领域） | 按「问题 → 现有解法 → 各自取舍 → 我的场景选哪个」组织，不按知识点组织 |
| 完全陌生，不知道有什么 | 先做一次侦察课：只产出领域地图（有哪些子领域、各自解决什么），不进入任何子领域 |
| 已有材料但很散 | 走 `course-generator` 把材料转课程，再回到本 skill 建 DAG |

## 七、反模式

- 按教材目录抄大纲：教材目录是作者的知识顺序，不是你的学习顺序
- 模块之间没有依赖，实际是并列清单：那不需要 DAG，直接用清单
- 每个模块都写「理解 X 的基本概念」：无法验收，等于没写
- 预算不留余量：第一次必然延期
- 一次性拆到 20+ 模块：拆得越细越容易停更，先粗后细

## 八、输出检查清单

出 `syllabus.yaml` 前逐条过：

- [ ] 成功判据能填空，且可验收
- [ ] 3-12 个模块（推荐 5-12），每个 ≤ 3 小时
- [ ] 每个模块有产出物，标题是动词短语
- [ ] `anchor.basis` 写得出「用哪本书哪版 + 哪份课标」
- [ ] 每个模块有 `textbook_ref`，能与基准对上
- [ ] 已做差集：基准里有而没讲的，都补了模块或进了 `not_covered`
- [ ] 每个模块有 `not_covered`（本模块不覆盖什么）
- [ ] `prereq` 无环、有入口、无孤立节点
- [ ] 每条 `why_prereq` 都写得出「缺了它会卡在 ___」
- [ ] 每个模块有 `check`（验收证据）
- [ ] 预算之和 ≤ 总预算 80%
- [ ] `resources` 里级 0-2 主源 ≥ 3 条且链接可开
- [ ] 用户已确认

## 九、起步只建 5 个文件

`MISSION.md` / `syllabus.yaml`（含 resources 注释区）/ `mastery.md` / `review.md` / `lessons/`。

`reference`、`mistakes`、`learning-records`、`assets` 按需生长。一次铺满 9 个文件的结果是第 3 天开始跳过其中一半。
