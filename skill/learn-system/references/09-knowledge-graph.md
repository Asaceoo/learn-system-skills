# 09 · 知识图谱总览（流程 A 第 3 步末）

大纲回答「学什么、什么顺序」，图谱回答「这些知识点之间是什么关系、每个点到底是什么」。
缺了图谱，学习者拿到的是一串待办；有了图谱，才知道自己站在网的哪个位置。

## 1. 什么时候出，写到哪

| 项 | 值 |
|---|---|
| 触发 | 大纲被用户确认后、出第一课之前（流程 A 第 3 步末） |
| 产物位置 | `study/<topic>/graph.html`，**topic 根目录下**，与 `syllabus.yaml` 同级（不是 `reference/`，那里只放速查件） |
| 数据 | `syllabus.yaml` 每模块下新增 `concept_cards`（7 个文本字段） |
| 呈现 | `study/<topic>/graph.html`（单文件、离线可开、可打印），照 `templates/graph.template.html` |
| 回填 | 每出一课，把该课概念的 `assumption` / `first_principle` / `plain` / `extend` 补实，图谱页同步更新 |

**不与铁律 2 冲突**：调研在出大纲之前已完成，图谱是调研结果的结构化表达，不是新的知识生产。
图谱页里写不出内容的字段，写「待补 + 为什么缺」，不许编。

## 2. 概念卡的六个字段（写在 `syllabus.yaml`）

**口径（唯一说法，全文不得再有第二种）**：每张卡 **7 个键** = `name` + **6 个内容字段**；
再算上 **2D / 3D 两张图**，即铁律 18 说的 **八项**。

> 「七字段」是早期笔误，凡见「七字段」一律按本节理解：指的是含 `name` 的 7 个键。

`concepts` 字符串列表保持不变（它是粒度与覆盖度的基准）；`concept_cards` 与它并列，
**两者概念名集合必须完全一致**，多一个少一个都算不一致。

```yaml
concept_cards:
  - name: "冷却时间"
    prereq: ["成型周期"]          # 概念级前置（可跨模块），无则写 []
    related: ["模具温度"]          # 相关但非前置：互相影响、常一起用、易混淆
    assumption: "前提是熔体在模内已充满并进入保压；若充不满，谈冷却时间没有意义"
    first_principle: "热传导 Fourier 定律：散热速率 ∝ 温差 × 接触面积 / 壁厚，壁厚平方级影响冷却时间"
    plain: "就像一大块冰和小块冰谁化得快——不是重量差一倍，是厚度差一倍时间差四倍"
    extend: "随形冷却水路、铍铜镶件、模温机选型；往熱流道与模流分析延伸"
```

每个字段的合格判据（写不出就是没想清楚，不许留空或用「同上」糊过去）：

| 字段 | 合格判据 | 常见糊弄 |
|---|---|---|
| `prereq` | 写概念名；跨模块的前置也允许；确实无前置写 `[]` | 把整模块写进来、写「无」而不解释 |
| `related` | 至少 1 个同类概念；说清是「互相影响 / 常一起调 / 易混淆」里的哪一类 | 把 related 写成 prereq |
| `assumption` | 一句「前提是 ___；不成立时会怎样」 | 只写「假设理想状态」 |
| `first_principle` | 追到一个不再追问为什么的定律/守恒律/定义，并写出推导方向 | 停在「经验上就是这样」、只复述结论 |
| `plain` | 用一个生活类比讲给外行，类比要**对齐机制**而不是只对齐表象 | 类比与机制无关（「就像开车」） |
| `extend` | 至少给一个「学完这个可以往哪走」，指向具体技术/章节 | 写「深入学习」 |

**断言三级同样适用于概念卡**：字段值里写判断性内容时，在括号里标注级别，
如 `assumption: "...（建议·单源）"`、`first_principle: "...（推断：若 X 则本条不成立）"`。
不另设 `evidence` 字段——级别跟着值走，避免又多一个要同步的列表。

## 3. 图示（落在 `graph.html`；课内只链接不重画）

每个概念都要有 **2D + 3D** 两张图，**落在 `graph.html`**（不要求课内重画一遍）。
课里讲到该概念时，链接到图谱页对应卡片锚点即可——重复画两张图只会让每课变重。

- **2D 图示**：内联 SVG。画关系与结构（流程、对比、剖面、参数曲线）。
- **3D 图示**：内联 SVG **等距（isometric）投影**，或纯 CSS `transform: rotateX/rotateY` 的小部件。
  用来表示空间结构、层叠、体积关系。

硬约束（与「单文件离线可开」冲突时的处置）：

- **禁止外链 Three.js / 任何 CDN 的 3D 库**——外链一断，图就没了，课也不离线了。
- **禁止外链图片**（`src="http..."`）；图必须内联（SVG 直接写进 HTML，或 `data:` 内联位图）。
- 做不到真 3D 就用等距 SVG，这本身就是达标的 3D 图示，**不算降级，不用额外声明**。

## 3.1 三种容易含糊的情况（明确到可判定）

| 情况 | 规定 |
|---|---|
| 同一对概念**既在 `prereq` 又在 `related`** | 只画**实线前置**，不重复画虚线；卡片里两类都写出来。前置优先，因为「必须先学」的信息量更大 |
| 图注 / 图示里出现**无一手来源的数值** | 标「（数值待核验）」并在 `coverage_gap` 记一条，写明去哪核验。**不许因为「图里看起来专业」就写死数字** |
| 处于**无来源环境**（不联网、无一手材料） | 断言级别标「（待核验：去哪查）」，这是第三档的变体；不要因为标不了「单源」就干脆不标 |

## 4. 图谱页长什么样（`graph.html`）

1. 顶部一张 **2D 图谱**：节点 = 概念，实线箭头 = 前置，虚线 = 相关，按模块分色分区。
2. 下面每个概念一张卡：`前置 / 相关 / 前提假设 / 第一性原理 / 通俗说明 / 扩展` **各占一行** + `2D / 3D` 两张图。
3. 卡片按模块分组，与 `syllabus.yaml` 顺序一致。
4. 已上过的概念标出掌握档（读 `mastery.md`），没上的留空——**图谱同时是进度视图**。

## 5. 铁律 18（与铁律 4 的关系）

铁律 4 说「每个概念必须出现在某课正文或速查件」；
**铁律 18 加一层：每个概念必须有完整的 7 字段 + 2D/3D 两张图，缺一项不算覆盖。**
两关都要过：出现在课里 ≠ 讲清楚了。

## 6. 交卷清单（出图谱时逐项打勾，每条贴证据）

- [ ] `concept_cards[].name` 与 `concepts` 集合完全一致（`python` 比对两个集合的实际输出）
- [ ] 每张卡 7 个字段都非空，且符合 §2 的合格判据
- [ ] `prereq` 构成的图**无环**（拓扑排序实际跑通的输出）
- [ ] `graph.html` 已生成，`ls` 有该文件
- [ ] 每个概念在 `graph.html` 里都有 2D 与 3D 两个图区块（`grep -c` 实际计数 = 概念数 × 2）
- [ ] `graph.html` 内**无外链**（`grep -c "src=\"http" / "cdn" / "three"` = 0）
- [ ] 图谱页导航**按当前进度如实写**：还没出课时写纯文本「上一课/下一课：待产出」，
      **不要写 `href`**（此时链过去就是断链）；首课产出后再补双向链接

## 7. 降级

| 缺什么 | 怎么办 |
|---|---|
| 画不出 3D | 用等距 SVG（达标，不声明降级） |
| 概念太多（>40）图谱画不下 | 分模块画多张图，首页只放模块级图 + 链接 |
| 图示画不完 | **任何规模都允许写可复用的绘制脚本批量生成，这属于常规手段，不是降级**（照抄同一张占位图才是糊弄）；仍做不到则按 `core` 集合降级，并写明「本次覆盖 X/N，跳过哪些」 |
| 某字段确实查不到 | 写「待补：<查什么、去哪查>」，在 `coverage_gap` 记一条，**不许编** |

## 8. 反模式

- **图谱画成目录**：只有层级没有依赖边，等于把大纲重抄一遍
- **related 写成 prereq**：把「相关」全画成箭头，图谱变成一张全连接的网，没有信息量
- **第一性原理只复述结论**：写「因为热传导」但没追到 Fourier 定律
- **类比不对齐机制**：「就像开车」这种只对齐了「需要操作」这一个表象
- **图外链 CDN**：当下能看，离线就白图
