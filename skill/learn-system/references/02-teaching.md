# 教学法：怎么让一课真的留下东西

核心区分只有一句：**当场能想起（流畅度）不等于长期记住（存储强度）。** 流畅度会骗人，读第二遍很顺 = 什么都没记住。本文件所有规则都服务于存储强度。

## 一、知识与技能，难度反向

| | 目标 | 难度是 | 做法 |
|---|---|---|---|
| 知识 | 获取（先懂） | **敌人**——吃工作记忆 | 拆小、加类比、给最小例子、去掉无关细节 |
| 技能 | 留存与灵活（会用） | **工具**——努力提取才建存储 | 逼回忆、加变式、交错练、延迟反馈 |

同一课里两者都有。讲概念时降难度，练技能时加难度。把两者混着做，两边都不成。

## 二、一课只推进一个能力点

- 判据：能用一句话说出「这一课之后，用户能做一件之前做不了的事」。
- 说不出就拆课，不要塞。
- 一课的工作记忆预算约 4 个新概念。超了就拆到后续课。
- 允许一节课只纠正一个误解——纠正误解比新增知识更值。

## 三、最近发展区（ZPD）

每课必须落在「跳一跳够得着」：

1. 读 `mastery.md`，找已到 L2 但未到 L3 的概念 → 优先教这些的下一步。
2. 找 `syllabus.yaml` 里当前模块未被任何课覆盖的概念。
3. 两者交集就是本课内容。交集为空时：先补前置，或推进到下一模块。

**太难和太易都是浪费。** 用户连续两课无明显进展 → 说明 ZPD 判断错了，回退一个层级重讲，并在 `learning-records/` 记录。

## 四、知识部分怎么写

固定五段，顺序不要变：

1. **它解决什么问题**——先给痛点，不给定义。没有痛点就不该学它。
2. **它是什么**——一句话定义，不超过 25 字。
3. **它和相邻概念的区别**——至少一个对照 + 一个反例。这一步比定义更重要。
4. **最小例子**——小到能在一屏内看完，能手动跑一遍。
5. **常见误区**——写「新手会以为 X，实际是 Y，因为 Z」。

类比的使用边界：类比用于建立直觉（第 1 段），定义用于收口（第 2、3 段）。**不要用类比替代定义**，也不要在类比里引入比原概念更难的东西。

## 五、技能部分怎么练

三类练习，一课至少一类：

| 类型 | 形式 | 检验什么 |
|---|---|---|
| 提取 | 合上材料复述/默写 | 有没有真的记住 |
| 变式 | 换条件重做同一题 | 会不会迁移，还是背了答案 |
| 纠错 | 给一段有错的材料找错 | 有没有真理解边界 |

练习必须**立刻可做**、**立刻可判**。做不到自动判分就写清判定标准，让用户自评。

## 六、五个难度调节旋钮

用户说「太浅」或「太难」时，按顺序调，一次只调一个：

1. **例子复杂度**（最轻）——换更真实的例子
2. **前置假设**——假设更多已知，跳过推导
3. **抽象层级**——从具体操作升到原理，或反过来
4. **练习强度**——变式题 / 组合题 / 开放题
5. **范围**（最重）——加模块或砍模块，走流程 E

不要一次全调，否则判断不出哪个起作用。

## 七、五个学习视角（按需插入，不默认全用）

来源：Bloom 的 learn-* 家族。默认只用第 1 个，其余按信号触发。

| 视角 | 何时用 | 做法 |
|---|---|---|
| 图景（graph） | 概念多、关系乱 | 先画一张「依赖什么 / 支撑什么」的图，再进细节 |
| 跨界（crossover） | 用户已有相邻领域经验 | 用他会的领域做锚点，指出同构与不同构 |
| 奥卡姆（occam） | 用户想学得太深或太浅 | 先框定「这个场景需要学到哪一层就够」，砍掉不必要深度 |
| 原型（prototype） | 技能型、能动手 | 先做一个最小可跑的东西，再回头讲原理 |
| 费曼（feynman） | 自认为懂了 | 让他用大白话讲给外行，找出讲不下去的断点 |

费曼视角的判据很硬：**讲不下去的地方就是没懂的地方**，不要用「表达问题」当借口。

## 八、语气与节奏

- 中文主讲，专业术语、公式、代码标识符保留原文。
- 不夸人。鼓励要具体到「你这一步的推理是对的，因为……」。
- 用户卡住时先分类，再给方案：概念不清 / 练习不足 / 缺反馈 / 资料过载 / 任务设计失真。五类对策不同。
- 不要一次抛三个问题。一次一个，等回答。

## 九、反模式

- 讲完就结束，没有练习 → 只建了流畅度
- 练习是「你觉得懂了吗」→ 不是证据
- 一课塞五个概念，每个讲两句 → 全部遗忘
- 用类比讲完就收工，没给精确定义 → 用户会用错边界
- 直接给答案，不给推理链 → 下次换个壳就不会
- 复习时重讲一遍 → 那是重学，不是复习
