# 掌握度：五档判定与证据协议

掌握度是这张表里唯一可信的「你学到哪了」。它必须可判定、可追溯、可降级。

> 术语：本文件的「档位」特指**掌握档 L1-L5**，与 `05-review.md` 的**复习档 0-5** 是两套刻度，不换算。填表时不要互相抄。

## 一、五档定义

| 档 | 名称 | 表现 | 仍然不算掌握的信号 |
|---|---|---|---|
| L1 | 知道 | 能复述定义、认得出术语、知道它大致解决什么问题 | 一离开定义就解释不了；举不出例子；分不清邻近概念 |
| L2 | 会用 | 能跟着示例完成基本应用；能在熟悉场景重复使用 | 一换语境就失灵；会套模板但说不清为什么 |
| L3 | 会改 | 能修改已有解法/材料；能发现错误、缺漏、边界条件；能用自己的话重组 | 只会改表面；改完说不清影响 |
| L4 | 会设计 | 能从目标反推做法；能解释为什么选这个而非那个；能拆成可完成的小块 | 只在给的框架内能设计；条件一变就崩 |
| L5 | 会迁移 | 能迁到新主题新场景；能抽出通用模式；能给别人讲并给反馈 | 只能讲自己学过的例子 |

**L3 是分水岭。** 低于 L3 一律不算掌握，`syllabus.yaml` 的前置校验也卡在 L3。

### L3 在两类领域的不同观测法

「会改」对技能型好判断，对知识型不好判断。按领域类型换成可观测行为，判据不变（都是「能发现问题并修正」）：

| 领域类型 | L3 怎么观测 | L4 怎么观测 |
|---|---|---|
| 技能型（编程、写作、乐器） | 给一段有缺陷的作品让他改，改完能说清影响 | 从目标反推做法，换条件仍成立 |
| 知识型（历史、理论、法条） | 给一段有错误的论述让他挑错并给出正解；或给出两种对立解读让他判据 | 能用该框架解释一个他没学过的案例 |
| 混合型（产品、管理） | 给一个真实案例让他指出方案漏洞 | 给定约束下的方案设计与取舍说明 |

知识型领域若只用「复述 + 选择题」，永远到不了 L3——这是最常见的假掌握来源。必须加「纠错」或「辨析」类证据。


## 二、证据协议

判定必须至少两类证据，且至少一类是**产出型**。单一证据一律封顶 L2。

**判定方分界**：agent 只判「有唯一答案且能机器验证」的题；其余必须自评。表外类型不得用于升档。

| 证据类型 | 强度 | 判定方 | 说明 |
|---|---|---|---|
| 复述 / 默写 | 弱 | 自评 | 只能证 L1 |
| 选择题答对 | 弱 | **agent** | 只能证 L1-L2，可能蒙对 |
| 改错题 | 中 | **agent** | 有标准错点，能证 L3 |
| 变式题 | 中 | **agent**（有标准答案时） | 能证 L3 |
| 小实现 / 小推导 | 强 | **agent**（能跑通/能验算时） | 能证 L3-L4 |
| 资料重组（自己重画结构） | 强 | 自评 | 能证 L4 |
| 用在自己的项目里 | 强 | 自评 | 能证 L4-L5 |
| 给别人讲并被追问不崩 | 强 | 自评 | 能证 L5 |

**自评的硬要求**：不只说「我会了」，必须写出一句「我能独立做到 ___」。写不出具体描述，该证据按 L2 封顶，不得升到 L3。

反例（不算证据，见到就退回）：
- 「听懂了」「有道理」「原来如此」
- 「看完了」
- 连续答对简单题
- 用户复述了你刚说过的话（是短期记忆，不是掌握）

## 三、判定动作

每次测评后对每个概念执行：

1. 列出本次得到的证据类型。
2. 按上表取**最低档但不超证据上限**的档位。例：只有复述 → L1；复述 + 改错题 → L3。
3. 与旧档位比较：
   - 新 > 旧：升档，写证据
   - 新 = 旧：不变，更新「最近测评」日期
   - 新 < 旧：**降档必须先写原因**（久未复习 / 发现前置有洞 / 上次误判），不写不降
4. 档位变动记入 `mastery.md` 的 `last_change` 列。

## 四、mastery.md 表结构

```markdown
## 当前状态
- 当前模块：M02
- 下一课：0003 冲突标记三段怎么读
- 到期复习：3 条
```

> 这三行是唯一恢复入口。新会话只读这个区块就能接着走，不必扫其他文件。每次更新 mastery 都要同步刷新。

```markdown
| 概念 | 模块 | 掌握档 | 证据 | 判定方 | 最近测评 | 变动 | 备注 |
|---|---|---|---|---|---|---|---|
| 闭包捕获 | M02 | L3 | 改错题+小实现 | agent/自评 | 2026-10-30 | L2→L3 | 边界条件仍弱 |
```

规则：
- 概念名一经确定不改。要改就同时改 `syllabus.yaml` 的 `concepts`，并在 `learning-records/` 记一笔。
- 「证据」列写类型组合，不写分数。
- 概念数上限 60 行。超了先合并到「能力」层级（例：把「for 循环 / while 循环 / 递归终止」合成「循环控制」），仍超再按模块拆文件，`mastery.md` 只留索引。

## 五、仪表盘（写在 mastery.md 顶部）

```markdown
## 概览
- 总概念 23 · L1 4 · L2 6 · L3 8 · L4 4 · L5 1
- 已掌握（≥L3）13/23 = 57%
- 最薄弱模块：M03（均档 1.4）
- 最近更新：2026-10-30
```

只看两个数：**已掌握比例**、**最薄弱模块**。其余是过程数据。

## 六、前置门槛

进模块前：

1. 找出 `prereq` 里每个模块的全部概念。
2. 全部 ≥ L3 才放行。
3. 有未达项时，列出「缺哪几个概念、当前档位、补到 L3 预计几小时」，让用户选补前置 / 降目标 / 硬上。

## 七、常见误判

| 误判 | 后果 | 修正 |
|---|---|---|
| 把「流畅阅读」当掌握 | 复习时全崩 | 只用证据表判定 |
| 一次答对就升到 L4 | 后续课全塌 | 升级必须两类证据 |
| 长期不降档 | 仪表盘虚高 | 逾期 30 天未复习 → 先抽查 1 题再定档；抽查不过降 1 档并标「久未复习」，抽查通过只改到期日 |
| 概念粒度太粗（「函数式编程」当一个概念） | 无法判定 | 拆到可单题测验的粒度 |
| 概念粒度太细（每个 API 一个概念） | 表爆炸 | 合并到「能力」层级 |
