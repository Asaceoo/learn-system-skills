# 11 · 图面语法（所有图共用）

> **来源**：融合 `cathrynlavery/diagram-design`（GitHub，实测 63k+ star，2026-10-31 核对）。
> 它做的是**编辑级示意图**（架构图/流程图/数据看板），本 skill 做的是**教学图**。
> 所以只取它的**语法**（预算、删除测试、反模式、无障碍、宽度），**不取**它的 45 种图型全库、
> 品牌皮（Geist / Instrument Serif / 珊瑚色）、PNG 导出、draw.io 与 Mermaid 导入、动画。
> 理由见 §10「明确不并的部分」——每一条都与本 skill 的既有硬约束冲突。

本文件管**所有图**（课内机制图、图谱页结构图、速查件插图）。
`09-knowledge-graph.md` §3.2 的九种**机制图**图型仍然有效，两者叠加使用：先按本文件 §1 选类，再进 09 选型。

## 0. 什么时候**不**该画

三问，任一答「是」就不画：

1. 这段话读者读一遍就懂？
2. 一张两列表格能说清？
3. 去掉这张图，正文不缺任何信息？（说明它只是把正文重画了一遍）

> 原项目的原话：**最高质量的动作通常是删除。**
> 本 skill 的对应纪律：铁律 1「一次只产出一课」——图也一样，**一张图只回答一个问题**。

---

## 1. 选型：先定语义，再定图型

**第一步 · 定语义**（这张图在讲什么关系）

| 在讲什么 | 图类 | 去哪选型 |
|---|---|---|
| **为什么**——量之间的因果、趋势、上下限 | 机制图 | `09` §3.2 九种（坐标曲线 / 平台曲线 / 交叉窗口 / 响应曲面 / 梯度衰减 / 剖面层叠 / 流程状态机 / 对比条 / 层级树） |
| **多因一果**——一个结果的多类成因（缺陷排查、故障归因） | 结构图 | 本文 §2 **S6 因果鱼骨**（它是唯一允许「一果多因」的图型；机制图表达的是量与量的关系，表达不了分类穷举） |
| **有什么 · 在哪层 · 怎么递进** | 结构图 | 本文 §2 其余五种 |
| **多少 · 谁高谁低** | 数据图 | 本文 §2 后两种 |

**第二步 · 定图型**，并写出一句话：**这张图回答什么问题**（→ 进 `data-q`，必须是问句）。

> 反模式：跳过第一步直接挑图型。结果常常是「用流程图讲一个本该用曲线讲的连续量关系」——
> 图画得很整齐，但答不了「为什么」。

## 2. 结构图与数据图 八种

补 `09` §3.2 九种机制图之外的部分。**预算列是硬上限**，超了按 §3 拆图。

| # | 图型 | 回答的问题 | 用在哪 | 别用它做 | 预算 |
|---|---|---|---|---|---|
| S1 | **层叠 stack** | 这件事分几层？上下层是支撑还是并列？ | 技能分层（基础/进阶/专家）、材料由表及里、标准的三级文件体系 | 层级之间有回路时（那是依赖图） | ≤5 层 |
| S2 | **树 tree** | 谁包含谁、谁属于谁？ | 缺陷分类、材料家族、工艺分支 | 有交叉归属时（那是依赖图或 Venn） | ≤3 层 / ≤12 叶 |
| S3 | **包含 nested** | 范围套范围，我在哪一圈里？ | 工艺窗口 / 标准适用范围 / 公差带 | 表达「递进」时（那是时间轴或层叠） | ≤4 圈 |
| S4 | **时间轴 timeline** | 什么时候发生什么？顺序能换吗？ | 成型周期各阶段、工艺演进、学习计划 | 阶段之间有并行分支时（那是流程/泳道） | ≤8 节点 |
| S5 | **象限 quadrant** | 两个维度上各在哪？取舍在哪一格？ | 参数权衡（快 vs 稳）、方案对比、优先级 | 两个维度其实是同一个量时 | ≤9 点 |
| S6 | **因果 fishbone** | 一个结果的多类成因分别是什么？ | **缺陷排查**（飞边/缩痕/变形）、故障归因 | 要表达成因之间的传导链（那是流程/依赖） | 620px 宽下 **≤4 骨 × 1 条主因**（实测极限，再多必叠字） |
| S7 | **热力图 heatmap** | 多个对象 × 多个维度，哪格最烫？ | 掌握度矩阵、参数敏感度、材料×工艺适配 | 只有一行或一列时（那是条形图） | ≤12×8 格 |
| S8 | **条形 bar** | 谁高谁低？差多少？ | 数量对比、占比排序 | 长度与数值不成比例（那是在骗人） | ≤10 条 |

**八种都有可复制的骨架**：`assets/diagram-gallery.html`（由 `scripts/diagram_gallery.py` 生成，纯标准库）。
要画鱼骨或象限时，**照抄那张的结构、换标签、按数据改坐标**——不要从零算像素，手算坐标压线已经踩过五轮。

```bash
python scripts/diagram_gallery.py     # 重新生成到 assets/diagram-gallery.html
```

**图型 6 的特别说明**：fishbone 是本文件里**唯一**允许「一个结果对多个原因」的图型。
它的价值不在好看，在于**强迫你把成因分类**（人/机/料/法/环），而不是罗列现象。
本 skill 的用法：出缺陷类课程时，主图优先考虑 fishbone，而不是又画一条曲线。

## 3. 复杂度预算（每图）

| 项 | 上限 | 超了怎么办 |
|---|---|---|
| 节点 / 数据点 | **9** | 拆成「总览 + 细节」两张；总览只放模块级，细节图单独一张 |
| 连线 / 箭头 | **12** | 先删「布局已经能表达」的线；仍超就拆图 |
| 焦点元素（红点/高亮带/加粗） | **2** | 只留最该看的两处，其余降为普通样式 |
| 旁注 / callout | **2** | 其余写进正文，不要挂在图上 |

> 判据一句话：**超过 9 个节点的图，通常是两张图。**

**这条对图谱页同样成立**：`graph.html` 的**依赖总览图**若概念数 >9，只画到**模块级**（每模块一个节点），
概念级依赖拆到「模块细节图」，一个模块一张。**不许把 26 个概念塞进一张图**——
那不是全面，那是没人看得懂。

## 4. Remove test（出图前四问，逐条回答）

- [ ] 能删掉某个节点吗？读者还看得懂吗？
- [ ] 能合并两个节点吗？它们是不是总是一起出现？
- [ ] 能删掉某条线吗？关系从布局就能看出来吗？
- [ ] 能删掉某个标签吗？颜色或形状已经表达了吗？

四问里有任何一问能答「能」，就先改，再出图。

---

## 5. 出图前先声明（一句话）

动手画之前，先说清三件事：

> **图型 X · 回答「……」· 会砍掉 ……（因为超出预算 / 与主线无关）**

用户在场就让他改；不在（无人值守）就画完，把假设写进图注。
**只在你已经确知图型、尺寸、内容全部确定时才可以跳过这句。**

## 6. 通用反模式（命中任一条即返工）

这份清单是「AI 味示意图」的识别特征，逐条可查：

| 反模式 | 为什么不行 |
|---|---|
| 每个节点都是同样大小的方块 | 抹掉了层级，等于说「这些一样重要」 |
| 图例浮在绘图区内部 | 一定和节点/曲线打架；图例放底部横条 |
| 箭头标签没有底色遮罩 | 线会从字中间穿过去 |
| 竖排（`writing-mode`）文字压在箭头上 | 读不了 |
| 三张等宽卡片并排当默认版式 | 通用网格，没有主次；宽度要有差异 |
| 任何元素带阴影 | 阴影一律不用，用描边 |
| 圆角半径 >10px | 按钮感，不是图 |
| 同一种强调色标了 5 个「重点」 | 强调色是编辑手段，不是信号灯；本 skill 上限 2 处 |
| 装饰性插图 / 写实透视图 / 3D 爆炸图 | 增加认知负荷，不增加信息 |
| 图注写「如上图所示」「见图 2」 | 图必须能独立读懂 |
| 同一张图里塞两个焦点结论 | 拆图 |
| 用流程图表达并列关系 | 箭头会让人以为有顺序 |

## 7. 无障碍契约（可机检）

每张图必须满足，四条全过：

1. `<svg>` 带 `role="img"` **和** `aria-labelledby="<slug>-title <slug>-desc"`
2. `<title>` 是 `<svg>` 的**第一个子元素**（在 `<defs>` 之前），且 `<title>`、`<desc>` 都非空
3. id 带前缀（`<slug>-title` / `<slug>-desc`），**不许用裸 `title` / `desc`**（同页多图会撞 id）
4. `<title>` ≤60 字，写**这张图讲什么**；`<desc>` 一句话写**内容**，不写几何（不写「左边三个框」）

纯装饰图（分隔线、图标）改用 `aria-hidden="true"`，不进本契约。

> 早期版本写的是「`role="img"` + `aria-label` **或** `<title>/<desc>`」，二者其一即可 —— 口径太松，
> 实际两类图各写各的、都没法机检。现在收敛为上面四条，**只有一种写法**。

---

## 8. 手机宽度（两条，缺一不可）

- `<svg>` 的 `min-width` **等于** `viewBox` 的宽度（不许用 `width:100%` 让它无下限压缩）
- 外面套一层 `overflow-x: auto` 的容器

否则手机上会出现两种坏情况：整页跟着横向滚动，或者被祖先的 `overflow: hidden` 直接裁掉、连滚动条都没有。

## 10. 明确不并的部分（以及为什么）

原项目的能力里，下面这些**刻意不并**，理由都是与既有硬约束冲突，不是嫌麻烦：

| 它的能力 | 为什么不并 |
|---|---|
| 45 种图型全库（架构/ER/UML/部署/Sankey/Wardley…） | 服务对象是 IT 与商业汇报。学习场景用不上，且每种一个 reference 文件，体积会翻几倍 |
| 品牌皮：Geist / Instrument Serif / 珊瑚色 | 本 skill 的产物必须**单文件离线可开**，不能外链字体；配色要兼顾打印与浅底 |
| PNG / SVG 导出脚本 | 产物本身就是 HTML，浏览器打印即得 PDF；多一条导出链就多一处会坏的地方 |
| draw.io / Mermaid / Excalidraw 导入 | 导入会把对方的自动布局一起搬进来，等于放弃编辑级排版；本 skill 的图是手排的 |
| 动画 / 动效模板 | 「可打印、可 grep、离线可开」三条硬约束都与动画冲突；机制动画留给「连续 2 次没懂」时的借力产物 |
| 4px 网格的严格几何 | 坐标图的数据点位置由数据决定，不在网格上；只用网格约束框图类（S1/S2/S3） |

**取用边界一句话**：**它的语法照做，它的图型挑着用，它的皮和工具链一概不要。**
