# 10 · 组合产出（借力其他 skill）

本 skill 管「学到哪」，别处管「讲得多花」。**借力时控制权不转移**——这是全套规则的地基。

为什么不能设计成「A 自动调用 B」：按名字点名另一个 skill 并不保证它被加载（跨 skill 委派会静默失败）。
所以组合只能靠**接口契约 + 人工搭桥**：本 skill 出简报，用户带着简报去另一边，产物再回收进体系。

## 0. 升级到本版的老工作区，先补一行

`artifacts` 是 v0.8.0 才加进模板的字段。**已有课题的 `syllabus.yaml` 里没有它**，
此时第一次借力会无处登记、静默丢掉产物。升级后先手动补一行（就一行）：

```yaml
artifacts: []          # 加在 topic 块之后、modules 之前，或文件末尾任意顶层位置
```

补之前不要开始借力。审计 Z 段会检查真实工作区有没有这个字段。

## 1. 三种形态，只有一种日常用

| 形态 | 怎么运作 | 用不用 |
|---|---|---|
| **借力式** | 主流程某一步临时借一个能力，产物回收进 `reference/` 并登记 | **默认用这个** |
| 流水线式 | 多 skill 串联逐段交接（调研→大纲→深讲×N→汇编） | 大工程才用，每段都要人工确认 |
| 并行评审式 | 同一产物多视角审 | **不用**。AI 审 AI 边际收益极低，已实测过七轮 |

## 2. 产物矩阵（8 类，全套定义）

「触发条件」不满足就不要产出——**为了丰富而丰富，等于堆文件**。

| # | 产物 | 触发条件 | 谁产 | 落在哪 | 格式硬要求 |
|---|---|---|---|---|---|
| 1 | 单点课 | 按大纲推进 | 自产 | `lessons/NNNN-*.html` | 单文件离线、可打印、带即时判分自检 |
| 2 | 知识图谱页 | 大纲确认后 | 自产 | `graph.html` | 每概念八项、内联 2D/3D、零外链 |
| 3 | 速查件 | 压出可回看单元 | 自产 | `reference/<概念名>速查.html` | 单文件、一页能扫完 |
| 4 | **深讲卡** | **同一概念连续 2 次没懂**。**「看了两遍」只算 1 次**（一次阅读经历），别只看本表——详见下方辨析 | 借 `visual-knowledge-tutor` | `reference/<概念名>深讲.html` | 必须有动画或白板式分解；仍要单文件 |
| 5 | 交互课件 | 机制必须动手试才懂（如参数联动） | 借 `teachany` | `reference/<概念名>交互.html` | 可交互但**不得依赖联网**；体积 ≤ 2 MB |
| 6 | **模块手册** | **一个模块的课全部学完** | 借 `knowledge-handbook-builder` | 模块目录 `handbook/` | 章节顺序与 syllabus 一致 |
| 7 | 抽认卡 | 复习队列里档位 ≤1 的条目 ≥5 条 | 自产派生 | `reference/抽认卡.html` | 从 `mastery.md` + `review.md` 生成，一题一卡 |
| 8 | 音频 | 用户明确说要通勤听 | 借 TTS 能力 | `reference/audio/` | 一段课一个文件，命名带课号 |

**前三项是体系内建，不需要组合**。真正要「借力」的是 4-8。
**登记 `type` 只有 5 个**：`deep-dive / interactive / handbook / flashcards / audio`；
前三类（课/图谱/速查件）在固定位置、由状态模型管，**不填 `artifacts`**。

### 两个「2 次」不要混

| 说的是 | 触发什么 | 出处 |
|---|---|---|
| 同一概念**连续 2 次没懂**（用户说"没看懂/讲不通"） | 出**深讲卡**（换视角，材料不够） | 本文件第 2 节 |
| 同一概念**累计 2 次答错**（自检或复习答错） | 建 `mistakes.md` 记错因（不是材料问题，是理解偏了） | `references/05-review.md` |

区别一句话：**没懂 → 换讲法；答错 → 记错因**。两者都触发时先出深讲卡，错因等看完再记。

**「没懂」也要计数，别凭印象判第几次**：在 `mastery.md` 该概念行的**备注**列写「未懂 1」，
第二次再写「未懂 2」并出深讲卡。用户说「我看了两遍」算 **1 次反馈**（一次阅读经历），
不是 2 次——只有两次**独立的**「没懂」表达才累计。凭印象判"这是第二次"违反铁律 17 的同款精神。

### 每类产物的接口契约（借力时照 `templates/compose-brief.md` 填）

| 产物 | 给它什么输入 | 要它输出什么 | 回收时登记 |
|---|---|---|---|
| 深讲卡 | 概念卡的 `prerequisite` + `assumption` + `first_principle` + 该课里的卡点原话 | 一份 HTML，含「原来卡在哪 / 换什么视角 / 一张动画或白板分解」 | `artifacts` 加一行，`type: deep-dive` |
| 交互课件 | 该机制的参数列表与相互影响 | 一份可离线交互的 HTML | `artifacts`，`type: interactive` |
| 模块手册 | 该模块全部课 + 验收题 + `not_covered` | 一份可交付手册 | `artifacts`，`type: handbook` |
| 抽认卡 | `mastery.md` 的概念 + 档位 + 证据 | 一页卡片（正面问题/背面答案） | `artifacts`，`type: flashcards` |
| 音频 | 课正文（去表格、去代码） | 音频文件 | `artifacts`，`type: audio` |

## 3. 四条铁律（组合时生效，与 18 条同级）

1. **控制权不转移**：`mastery.md` 与 `review.md` **只由本 skill 写**。外部 skill 只产内容，不产状态。任何让外部 skill 改掌握度的做法都是错的。
2. **派活必须给已落盘输入**：不许口述「帮我讲讲萃取率」。要给概念卡（含前置/前提假设/第一性原理）——否则借来的东西和体系对不上，回来还得重讲一遍。
3. **产物必须登记**：外部产出写完后，在 `syllabus.yaml` 的 `artifacts` 记一行。**没登记的产物 = 下个会话不存在**，等于白做。
4. **格式不归一就不硬塞**：外部产的 HTML 若不符合本 skill 的导航/自检规范，**放 `reference/` 并在图谱页加链接，不要塞进 `lessons/`**。`lessons/` 的编号与顺序是状态的一部分，混进外来文件会让出课顺序错乱。

## 3.1 三条规则的优先级（打架时按这个顺序）

借力时最容易撞车的三处，**优先级从高到低**：

1. **材料缺失判断（§4）** —— 概念还没有独立一课 → 先补课，**任何情况下都不出卡顶替**
2. **不硬塞（§3 铁律 4）** —— 产物格式不合规 → 放 `reference/`，不进 `lessons/`
3. **降级产出（§6）** —— 只是借不到外部 skill → 自己做，照样登记

> 冲突示例（真机实测踩到）：概念没独立课 + 课在推进 + 借不到 tutor。
> §4 说「别出卡」，§6 说「自己做出来」——按本优先级，**§4 胜**，先补课。
> §6 只适用于「课已经有了，只是外部 skill 借不到」。

## 4. 什么时候**不**借

| 情况 | 为什么不借 |
|---|---|
| 一句话能说清的 | 借力本身有成本（填简报 + 切换 + 回收），比直接讲贵 |
| 外部 skill 会写自己的状态目录（如 `teach` 的 `./lessons/`） | 两套状态并存 → 恢复入口分叉 |
| 产物必须联网才能看 | 破坏「单文件离线可开」这条硬约束 |
| 已经连续 3 课在借力 | 说明大纲难度设置有问题，该回流程 E 调大纲，而不是继续加材料 |
| **这个概念根本没有自己的一课** | 属于「材料**缺失**」，不是「材料**不够花**」。先补课（流程 B），别用深讲卡顶替——附加材料替代不了课，也不会进 `lessons/` 的编号序列 |

## 5. 回收后的三件事（少一件都算没回收）

1. 文件落到上表规定位置
2. `syllabus.yaml` 的 `artifacts` 加一行（`name` / `type` / `path` / `source` / `created`）
3. 图谱页对应概念卡加一条链接（`深讲` / `交互` / `卡片`）

## 6. 降级

借不到时先看**这门课还继续吗**，两条路别走错：

| 情形 | 怎么办 | 落点 |
|---|---|---|
| 课还在推进（借力路径） | 自己用文字 + 内联 SVG 做完，照样登记 `source: self-fallback` | `reference/` + `artifacts` |
| 用户只要这一个概念、课先不上（切走路径） | 单点讲透，**不建 `study/`**，不入 `artifacts` | 对话里讲完即止 |

两种都要告知用户「动画版需切到对应 skill」。**不许因为切不过去就不做**，也不许假装做过。

## 7. 交卷清单（每次组合产出后打勾，每条贴证据）

- [ ] 触发条件真的满足了（不是"想多做点"）
- [ ] 简报填了 `templates/compose-brief.md` 的 6 个字段
- [ ] 产物落在规定位置（`ls` 实际输出）
- [ ] `artifacts` 已加行（`grep` 实际输出）
- [ ] 图谱页已加链接（`grep` 实际输出）
- [ ] `mastery.md` / `review.md` **没有被外部产物改动**（`git diff` 或前后对比）

## 8. 反模式

- **为丰富而丰富**：8 类产物全做一遍，但没有任何一个被真的用过
- **外部 skill 改状态**：让 tutor 顺手"顺手更新一下掌握度"——直接破坏唯一恢复入口
- **产物塞 `lessons/`**：外来 HTML 混进课序列，导航和编号全乱
- **产了不登记**：文件在 `reference/` 里，图谱页没链接，下个会话完全不知道它存在
- **一个概念借三次力**：第三次还讲不懂，问题在大纲粒度或前置缺失，不在材料不够花
