# learn-system 技术手册

> 版本：v0.6.1　|　面向：实现者、审查者、想改这个 Skill 的人　|　使用者请看 `USER_GUIDE.md`

---

## 1. 架构定位

**控制层，不是内容生成器。**

```
用户意图 → 路由表 → 主流程(A/B/C/D/E) → 读 references/*.md → 用 templates/* 产出 → 落盘 study/<topic>/
                                              ↑                                        ↓
                                        知识基准与规则                              状态回流（下轮读）
```

它只做三件别的 skill 不做的事：**前置依赖 DAG、概念级掌握度、复习调度**。动画、手册、交互课件外包给 `visual-knowledge-tutor`、`knowledge-handbook-builder`、`teachany`——但跨 skill 委派不可靠（点名不保证加载），所以降级为「建议切换 + 自带纯文字兜底」。

### 路径解析（两类，混淆会写错位置）

| 路径 | 相对谁 |
|---|---|
| `references/*.md`、`templates/*` | skill 目录 |
| `study/<topic>/*`、`./lessons/`、`./assets/` | 当前工作目录 |

已有课题可不在 `study/` 下：当前目录同时有 `syllabus.yaml` + `mastery.md` 即视为 topic 根。

## 2. 17 条铁律

全程生效。被要求跳过时先说清代价，再按用户意愿执行并记录偏离。

| # | 铁律 |
|---|---|
| 1 | 一次只产出一课，出完停下等反馈 |
| 2 | 调研先于出课且教材/标准锚定；找不到来源标「待核验」，不许编。调研是 topic 级（开课做一次）；后续课引用新来源须先补录。行业经验值归入「建议」并标「单源」 |
| 3 | 断言分三级：事实（带小节级来源锚点）/ 建议 / 推断（带可推翻条件），不许混写 |
| 4 | 覆盖度要验收：每个 `concepts` 必须出现在某课或速查件；与教材目录做差集；每模块写「不覆盖什么」 |
| 5 | 开课前必须有 MISSION：为什么学 / 什么算成功 / 不学什么 |
| 6 | 开课前必须有大纲，用户确认后才出第一课 |
| 7 | 每模块必须有前置依据「缺了它你会卡在 ___」；写不出就移到 `nice_to_have` |
| 8 | M01 完成时必须复审大纲（触发点是**模块完成**，不是第一课完成） |
| 9 | 进模块前校验前置：`prereq` 各模块 `core` 列表的概念须 ≥ L3；没写 `core` 取 `concepts` 前两个 |
| 10 | 每课结束必须更新 `mastery.md`；未答自检时写「已上未评」也算有效更新 |
| 11 | 判定要证据并写明判定方，证据表外的类型不得升档 |
| 12 | 自评必须写得出「我能独立做到 ___」，写不出按 L2 封顶 |
| 13 | 出题遵守零提示（选项字数相同、正确项位置打散、题干不含暗示词） |
| 14 | 复练不许重问原题，必须换语境 |
| 15 | 日期禁止心算：先用 `date +%F` 取当天再加减 |
| 16 | 不往个人目录根下写文件，退回 `~/Documents/learn-system/<topic>/` |
| 17 | 无证据不得升档，也不得为了让表格好看而给档位。与铁律 10 冲突时以本条为准 |

## 3. 主流程

### A 开课
1. 读 `MISSION.md`；缺失 → **弹窗**问三问（每问 2-4 个可点选项 + 汇总行 + 确认按钮），模式并入第 3 问
2. 深度调研：定基准 → 2 个独立目录 + 1 份课标 → 关键结论 ≥2 源交叉 → 记版次年份 → 写入 `anchor` / `resources`。主源不足 3 条可开链接不出课
3. 出大纲（3-12 模块，用 `templates/syllabus.template.yaml`）
4. 用户确认后走 B

### B 出一课（11 步）
1. 定这课教什么；上一课自检未作答**不影响继续**，但必须留痕
2. 读 `assets/` 复用组件；**样式一律内联**（不抽 `assets/lesson.css`，否则破坏单文件离线）
3. **先落状态，再写正文** ← 顺序是硬约束：mastery 写行（骨架行已存在则更新，不插重复行）+ review 入队 + 概念名一致；粒度以 syllabus 的 `concepts` 为准，正文不得自行拆并
4. 写 `lessons/NNNN-<中文概念名>.html`
5. 接导航：两边都改；下一课未产出时写纯文本，**不要写 href**
6. 课内必含：能力增量 / 练习 / 3-5 题零提示自检 / 主源链接 / 问老师入口
7. 只在压出可回看单元时才写 `reference/<概念名>速查.html`；**写了才允许链**
8. 用户答完自检后回填掌握档 + 证据 + 判定方
9. **交课前 7 项打勾，每项必须贴落盘证据**（`sed`/`grep`/`ls`/`date` 输出），只写「已完成」不算
10. 模块最后一课上完时执行铁律 8 复审
11. 停下，告诉用户下一课是什么

### C 复习
进入第一句先报「今天到期 N 条」→ 筛 `到期日 <= 今天`（逾期最久 → 复习档最低 → 上次忘记优先，最多 12 条）→ 抽问不重讲 → 三档评级 → 评「忘记」计一次错，**累计 2 次错**才建 `mistakes.md` → 回写两文件

### D 测掌握度
跨概念混合题（覆盖记忆/理解/应用/迁移）→ 按 `04-mastery.md` 重定档 → 输出掌握档表 + 三个最薄弱点 + 补强任务 + 复测时间

### E 调整与停更
改 `syllabus.yaml` 并记 `learning-records/`；目标变更必须先改 `MISSION.md`。停更三档：逾期 1 周砍模块 / 3 周改判据 / 6 周归档终止。

## 4. 数据模型

`syllabus.yaml` schema 见 `USER_GUIDE.md` §5。一致性规则（机器可验）：

| 规则 | 判据 |
|---|---|
| 模块数 | 3-12（推荐 5-12） |
| 每个模块预算 | ≤ 3 小时 |
| DAG | 无环、有入口、无悬空 `prereq` |
| 非空 `prereq` | 必须写 `why_prereq` |
| 总预算 | ≤ `horizon_weeks × weekly_hours × 0.8` |
| 每模块 | 必须有 `check`、`not_covered`、`textbook_ref`、`core` |
| `anchor.basis` | 必须能指出具体教材版本/课标 |
| `resources.primary` | ≥ 3 条且均有可开 url |
| `coverage_gap` | 每项 `decision` ∈ {added, not_covered} |

`mastery.md` 与 `review.md` 的关系：**两个刻度，不通约**。

- `mastery.md`：掌握档 L1-L5（学到什么程度）
- `review.md`：复习档 0-5（多久后复习），**记录复习后的档**

一致性规则：`review` 的概念集合 ⊆ `mastery` 的概念集合；`mastery` 顶部「到期复习 N 条」= `review` 的「今天到期 N 条」（队列总数写括号里）。

## 6. 审计脚本

```bash
python learn-system-audit.py    # 主审计：94 项（含 T/U 段），退出码非 0 即 FAIL
python tools/review_dialog.py   # 只跑弹窗专项 T 段（24 项）
```

两个脚本的关系：主审计在收尾前 `subprocess` 调用 `tools/review_dialog.py`，
失败则把「弹窗 T 段」计入 FAILS。真实源码 = `tools/review_dialog.py`，
仓库根的 `tools/audit.py` 是历史空文件，已删除。

分段：

| 段 | 检查 |
|---|---|
| A | 包完整性（16 文件） |
| B | frontmatter 可解析、体积 ≤ 14KB |
| C | **17 条铁律交叉引用是否指对**（语义关键词「最具体命中」判定，排除铁律正文内部自引） |
| D | 跨文件规则一致（如 mistakes 条件全局唯一） |
| E | 停更可执行性（`started_at` / `core` 字段存在） |
| F | 硬约束冲突（外链样式 vs 单文件离线） |
| G | SKILL.md → references/templates 引用链可解析 |
| H-K | 真实工作区产物：课区块、自检题、导航、HTML 合法性 |
| I | mastery/review 一致性、到期日算术、顶部三行 |
| J | 覆盖度缺口是否显式列出 |
| L-N | 规则可执行性（定位说明 / core 字段 / 导航约定 / 覆盖检查时机） |
| O | 模板自身无断链（不许出现 `reference/index.html`） |
| P | 口径一致（mastery 顶部 vs review） |
| Q | 盲测暴露的条款是否已补 |
| R | 跨文件术语与计数同步（README 的铁律条数、无「复习档位」残留） |
| T | **弹窗 24 项**：实现工具 / 模板存在 / 三问 / 选项数 / 汇总行 / 确认按钮 / 占位符 / 回写 / 未确认处置 / 双选 / 降级 / 体积 / 文档同步 / 字号≥11px / 换算表 / 不阻塞 / 无阴影 / CSS 变量 / sendPrompt / 字重 |

## 7. 四轮对抗性审查记录

方法：三视角（实现者自审 / 审查者脚本取真实报错 / AI 使用方盲测）+ 多轮收敛 + 清单兜底。

### 7.1 缺陷清单（16 项）

| # | 级 | 缺陷 |
|---|---|---|
| 1-2 | P0 | 铁律编号错引（「铁律 14 兜底」实为 16；「铁律 6 复审」实为 8 且触发点应是模块完成） |
| 3 | P0 | `lesson.template.html` 的 nav 指向不存在的 `reference/index.html` |
| 4 | P0 | 接管检测信号对本 skill 自身产物恒成立，每次「继续」都误报 |
| 5 | P0 | 铁律 10 与 11/12 在用户未答自检时互斥 |
| 6 | P0 | B2 抽 `assets/lesson.css` 与 B3 单文件离线冲突 |
| 7-8 | P1 | 缺 `started_at`（停更三档无法算）、缺 `core`（铁律 9 无法判） |
| 9-10 | P1 | 新会话定位 `study/<topic>` 未定义；未产出课导航未定义 |
| 11-12 | P1 | mistakes 条件三种说法；到期复习口径与 review 打架 |
| 13-15 | P2 | 调研粒度、概念命名、经验值归属未定义 |
| 16 | P2 | 上一课未反馈能否开下一课未定义 |

### 7.2 真机盲测（AI 使用方视角）

方法：隔离沙箱 + 一个**只读 SKILL.md** 的子代理，用户指令只有「继续」，不许提问。

| 轮 | 结果 |
|---|---|
| 1（修复前） | 12 个卡点；独立复现缺陷 1、2；自述「违反或绕过的规则」5 条 |
| 2（修复后） | 规则层面 16/16 已有明确规定；但**行为**上写出了 0002 却没更新 mastery/review —— **规则写清楚 ≠ 会被执行** |
| 3（收尾审计） | 确认三项全不合规 + 发现 0002 速查件断链；批评「清单是自评表不是验收表」 |
| 4（新流程） | 通过：落盘时间戳证明先落状态（01:53）后写正文（01:59）；7 项清单全贴证据；又暴露 6 个新卡点，已修 |

### 7.3 关键修复：从「自评表」到「验收表」

第三轮子代理的原话：**这份清单输在它问的是「你做了吗」，而应该问「证据呢」。**

采纳的两条结构性改动：

1. **改流程顺序**：更新 mastery/review 前移到写 HTML **之前**。即使写完长文件后崩溃或漏做，状态已留痕，铁律 10 就不会判定「这课等于没上」。漏做只影响丰富度，不影响可追溯性。
2. **清单要求落盘证据**：7 项每条必须贴 `sed`/`grep`/`ls`/`date` 的实际输出，只写「已完成」不算打勾。

### 7.4 审查工具自身也被审查（3 处）

| 缺陷 | 修法 |
|---|---|
| 语义匹配器假阴性：关键词命中并列时选错，放过真错引 | 改「最具体命中」+ 并列时取关键词更长的 |
| 铁律正文内部交叉引用被误判 | 排除铁律区块内的引用 |
| 「lesson.css」否定语境（「不抽」）未识别 | 加否定词识别 |

### 7.5 第五轮：弹窗专项（三视角 + 两轮盲测）

| 视角 | 抓到了什么 |
|---|---|
| 工具实现者（脚本取真实报错） | 11 项真错：未声明实现工具、无弹窗模板、汇总行/确认按钮只写在 SKILL.md 而模板里没有、答案不回写 `MISSION.md`、未确认无处置、无弹窗无降级 |

| 问题 | 修复 | 断言 |
|---|---|---|
| 弹窗没有可复现形态 | 新建 `templates/intake-dialog.template.html` | T02-T05、T07、T09、T10 |
| 答案不落盘 | 新建 `references/08-intake-dialog.md`，规定回写字段 | T11a/T11b |
| 未确认 / 只选部分 / 回散装文字 | 细则 §5 四种情况各有处置，一律「不许卡住」 | T12 |
| 无弹窗能力 | 降级表补「退化为三行编号纯文本」 | T14 |
| 平台规范违规 | 去 box-shadow、字重降到 400/500、字号 ≥11px、改 CSS 变量适配暗色 | T18、T21、T22、T24 |
| 点了还得手抄代号 | 确认按钮接 `sendPrompt`，无此函数时退化提示 | T23 |
| 预期完成时间算不出 | 细则补「每周小时 → horizon_weeks」换算表（D1 12 周 / D2 5 周 / D3 3 周） | T19 |
| 卡在「不学什么」 | 铁律 5 改为「可留待大纲确认时补」 | T20 |
| 审错对象 | 主审计改读仓库副本，新增 U 段逐文件比对已装副本；`build.py` 打包前自动 `deploy()` | U 段 |

体积约束：本轮净增 5 条规则，SKILL.md 仍在 14 KB 红线内（14306 B）——
靠重写冗余表述腾出空间，没有再次抬高阈值。细则外移到 `references/08`，SKILL.md 只留一行指针。

## 8. 设计取舍

| 决定 | 理由 | 代价 |
|---|---|---|
| SKILL.md 上限 12KB → 14KB | 规则可执行性优先；14.3KB ≈ 4.5K tokens 仍可控 | 首次加载多约 0.6K tokens |
| 分工表外移到 `07-routing.md` | 腾体积，非常驻内容不必常驻 | 多一次文件读取 |
| 复用档 0-5 而非 FSRS | 零依赖，够用 | 调度精度低于 FSRS |
| 复习不做推送，进入时先报数 | 不引入外部依赖 | 依赖你主动打开 |
| mistakes 用「累计 2 次」而非「连续」 | 「连续」需额外维护计数 | 阈值略宽松 |
| 委派降级为「建议」 | 跨 skill 点名不保证加载 | 需要用户手动切 |
| 不承诺知识正确 | 模型无法自证；承诺正确只会得到更自信的编造 | 用户必须抽查 |

## 9. 已知局限

1. 盲测只覆盖「继续 → 出下一课」一条路径；A/C/D/E 四条路径未盲测
2. 停更三档需真实拖延 1/3/6 周才能验证
3. 掌握度升档闭环需真人作答自检后才成立
4. 盲测是同一模型族，换模型族可能暴露不同理解偏差
5. 教材本身会错（尤其工艺类滞后于现行标准），所以教材排在标准与你的一手材料之后

## 10. 构建与版本

```bash
python build.py              # 递增 patch → 同步三份文档版本号 → 部署到已装副本 → 打 zip
python build.py --bump minor
python build.py --no-bump    # 只打包
python learn-system-audit.py # 校验，退出码非 0 即 FAIL
```

`VERSION` 是版本号唯一真源；`build.py` 递增后会把新版本号写入 README、用户手册、技术手册。

**部署步骤不是可选项**：仓库副本（`skill/learn-system/`）与已安装副本
（`~/.workbuddy/skills/learn-system/`）是两个独立文件树，只改仓库不部署 = 跑的还是旧副本。
`build.py` 在打包前自动 `deploy()`；审计 U 段会比对两份，不一致直接 FAIL。
