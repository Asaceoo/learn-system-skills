## 1. 架构定位

**结论先行：它是一个控制层，不是内容生成器。**

这句话不是修辞，是约束。内容生成器可以随便发挥，控制层必须可被机检、可被审计、可复现。

| 层 | 负责 | 不负责 |
|---|---|---|
| 控制层（本 skill） | 学什么 / 什么顺序 / 到什么程度 / 何时复习 | 不生产知识、不做原创研究 |
| 内容层（课/图谱/速查件） | 把调研发结果讲清楚 | 不决定讲什么、不决定讲多深 |
| 执行层（宿主 Agent） | 调工具、写文件、渲染弹窗 | 不越权改规则 |

推论：**每条规则都必须能写成一个可判定的断言**。写不成断言的规则，等于没有规则。

### 1.1 路径解析（两类，混淆会写错位置）

| 路径形态 | 实际位置 |
|---|---|
| `references/*`、`templates/*` | skill 自己的安装目录 |
| `study/<topic>/*` | 当前工作目录下的 `study/<topic>/` |

历史坑：曾把课写进 skill 目录（因为 `references/` 是相对的）。现在解析规则写在 SKILL.md 状态模型里，审计 G 段校验引用链可解析。

## 2. 18 条铁律

铁律是「全程生效」的硬约束，被要求跳过时先说清代价，再按用户意愿执行并记录偏离。

| # | 铁律 | 为什么存在 |
|---|---|---|
| 1 | 一次只产出一课 | 批量产出 = 质量失控，且用户来不及反馈 |
| 2 | 调研先于出课，且教材/标准锚定 | 模型的记忆会过时、会缝合、会编书名 |
| 3 | 断言分三级（事实/建议/推断） | 混写会让「猜测」冒充「事实」 |
| 4 | 覆盖度要验收（教材差集） | 防「假全面」：没讲的必须显式声明 |
| 5 | 开课前必须有 MISSION（不学什么可留待大纲确认时补） | 没目标就没有剪裁依据 |
| 6 | 开课前必须有大纲，用户确认后才出第一课 | 方向错了越走越远 |
| 7 | 每模块必须有前置依据（缺了会卡在哪） | 写不出依据 = 不是硬前置 |
| 8 | M01 完成时必须复审大纲 | 学完第一模块才有判断力 |
| 9 | 进模块前校验前置（`core` ≥ L3） | 前置没到就进，后面全崩 |
| 10 | 每课结束必须更新 `mastery.md` | 不落盘 = 等于没上 |
| 11 | 判定要证据并写明判定方 | 防止「感觉学会了」 |
| 12 | 自评必须写得出「我能独立做到 ___」 | 写不出按 L2 封顶 |
| 13 | 出题遵守零提示 | 有提示的题测不出掌握 |
| 14 | 复练不许重问原题，必须换语境 | 记住题目 ≠ 学会概念 |
| 15 | 日期禁止心算，用 `date +%F` | 手算已实测出过错 |
| 16 | 不往个人目录根下写文件 | 别在桌面堆垃圾 |
| 17 | 无证据不得升档（与 10 冲突以本条为准） | 消解 10 与 11/12 的互斥 |
| 18 | 每概念须有图谱六字段 + 2D/3D 两图 | 铁律 4 只管「出现过」，本条管「讲清了」 |

**铁律 4 与 18 的关系**：两关都要过。出现在课里 ≠ 讲清楚了。

**铁律 10 与 17 的关系**：用户没答自检时，10 要求「留痕」，17 要求「不升档」。
折中是「已上未评」状态——既留了痕，又没给档位。

## 3. 主流程

### A 开课（4 步）

1. 读 `MISSION.md`；缺失 → **弹窗三问**（`show_widget`，细则 `references/08`）
2. **深度调研**（`references/06`）：定基准 → 2 个独立目录 + 1 份课程标准 → 关键结论 ≥2 源交叉 → 记版次年份
3. 出大纲（`references/01`）：3-12 模块，每模块有 prereq / why_prereq / concepts / core / deliverable / budget / check / not_covered
4. **出图谱**（`references/09`）：每概念六字段 + `graph.html`（2D、等距 3D）

### B 出一课（11 步）

关键设计：**先落状态，再写正文**（第 3 步在前，第 4 步在后）。

原因：AI 写完一个 20 KB 的 HTML 之后，收尾步骤（更新 mastery/review）极易漏掉。实测过：
第 2 轮盲测产出了 0002 但没更新 `mastery.md`。把状态写在前面，漏不掉。

```
1. 读 mastery + syllabus + 上一课反馈 → 定这课教什么
2. 读 assets/，样式一律内联（不抽 lesson.css，否则破坏单文件离线）
3. 先落状态：mastery.md 写行 / review.md 入队 / 概念名一致
4. 再写正文：lessons/NNNN-<概念名>.html
5. 接导航（两边都改；未产出写纯文本不写 href）
6. 课内必含：能力增量 / 练习 / 3-5 题零提示自检 / 主源链接 / 问老师入口
7. 只在压出可回看单元时才写速查件；写了才允许链
8. 用户答完自检后回填掌握档
9. 交课前逐项打勾（7 项，每项贴落盘证据）
10. 模块最后一课上完 → 铁律 8 复审大纲
11. 停下等反馈
```

### C 复习 / D 测掌握度 / E 调整与停更

- C：先报「今天到期 N 条」→ 按逾期最久排序 → 只抽问不重讲 → 评级三档
- D：跨概念混合题（记忆/理解/应用/迁移）→ 判分后按证据表重定档
- E：逾期 1 周砍模块 / 3 周改判据 / 6 周判定失败整体移入 `_archive/`

## 4. 数据模型与一致性规则

### 4.1 文件与职责

```text
study/<topic>/
├── MISSION.md              # 为什么学 / 什么算成功 / 不学什么
├── syllabus.yaml           # 模块 + 概念 + concept_cards + anchor + coverage_gap + resources
├── graph.html              # 知识图谱总览（依赖图 + 每概念八项）
├── mastery.md              # 掌握档 L1-L5（唯一恢复入口）
├── review.md               # 复习档 0-5 + 到期队列
├── lessons/NNNN-*.html     # 一次一个能力点
├── reference/*.html        # 速查件（按需）
├── mistakes.md             # 同一概念累计 2 次错（按需）
├── learning-records/       # 目标/大纲变更（按需）
└── assets/                 # 第二课起要复用样式时才建（按需）
```

### 4.2 两条刻度（不可通约）

| 刻度 | 文件 | 取值 | 含义 |
|---|---|---|---|
| 掌握档 | `mastery.md` | L1-L5 | 学会了多少（能独立用到什么程度） |
| 复习档 | `review.md` | 0-5 | 多久会忘（决定下次间隔） |

**不换算、不推导、不互为代理。** L3 不代表复习档 3。

### 4.3 一致性规则（审计强制）

| 规则 | 违反后果 | 审计段 |
|---|---|---|
| `concept_cards[].name` 集合 == `concepts` 集合 | 覆盖度与图谱对不上 | V26 |
| 概念卡四字段无空值 | 铁律 18 没落实 | V27 |
| 概念级 `prereq` 无环 | 出课顺序算不出来 | V22 |
| `mastery.md` 概念 ⊆ `syllabus` 全部 concepts | 多出的概念无来源 | J |
| `review.md` 队列 ⊆ `mastery.md` | 复习了没学过的东西 | I |
| `mastery.md` 顶部「到期复习 N 条」== `review.md` 实际到期数 | 恢复入口说谎 | P |
| 概念名在所有文件里完全一致 | 同义名会让覆盖度检查失效 | B9 |

### 4.4 `concept_cards` 结构

```yaml
concept_cards:
  - name: "冷却时间"          # 必须与 concepts 里的写法完全一致
    prereq: ["成型周期"]       # 概念级前置，可跨模块
    related: ["模具温度"]       # 相关但不是前置
    assumption: "前提是 ___；不成立会 ___"
    first_principle: "追到 ___ 定律：___ → 推导方向 ___"
    plain: "就像 ___（对齐机制）"
    extend: "往 ___ 走"
    evidence: "教材A §4.2（事实）"   # 可选：有来源锚点时写
```

**为什么 `concepts` 和 `concept_cards` 是两个列表**：
`concepts` 是字符串列表，被铁律 4（覆盖度）、铁律 9（`core` 前置校验）、审计 J 段依赖；
改成对象会破坏这些既有逻辑。`concept_cards` 并列存在，用审计保证两者集合一致——
用一条断言换来向后兼容。

### 7.12 收敛后的关键教训

1. **规则写清楚 ≠ 会被执行。** 修法是改流程顺序（先落状态再写正文）、把自评表改成验收表（每项贴落盘证据）。
2. **审计脚本自己也会假绿。** 三个来源：用 `print` 而非 `chk()`、正则被近义词蒙混、**审错了对象（仓库 vs 已装副本）**。
3. **多文件批量替换必须事后 grep 复验。** 曾因脚本中途异常静默跳过后 3 处替换。
4. **从旧备份取数据等于丢数据。** 本轮搬运概念卡时，备份是子代理工作之前的，26 张卡全空。
5. **AI 会为了满足铁律自造字段。** 发现它加了 `evidence` 时，先问「是不是我的规则漏了」，而不是直接删。

## 8. 设计取舍

| 取舍 | 选择 | 代价 | 为什么划算 |
|---|---|---|---|
| SKILL.md 体积 | 硬顶 **15 KB**（原 14 KB） | 写规则时仍要腾字节 | 每次会话都要加载，膨胀直接吃上下文 |
| 14 → 15 KB 的调整 | 上调 1 KB | 多约 300 tok/会话 | 14 KB 时余量只剩 **12 字节**，为几个字节反复改措辞已发生 4 轮，成本超过收益；15 KB ≈ 4.6K tok 仍在合理区间 |
| 概念数据结构 | `concepts`（字符串）+ `concept_cards`（对象）双列表 | 两个列表要同步，多一条断言 | 改成对象会破坏铁律 4/9 与 J 段的既有逻辑 |
| 3D 图示 | 等距 SVG，禁 Three.js | 不能旋转、不是真 3D | 外链一断整张图就白，破坏「单文件离线可开」 |
| 图谱时机 | 大纲确认后（不是调研前） | 大纲与图谱分两次确认 | 调研前写第一性原理必然编造（违反铁律 2/3） |
| 弹窗形态 | widget 卡片 + 代号制 | 依赖平台渲染能力，需降级路径 | 三次点击替代三行打字；代号解决了「点了 AI 收不到」 |
| 复习与掌握 | 两个刻度不换算 | 用户要记两个数字 | 换算会把「学会了」和「没忘」混成一件事 |
| 审计形态 | 独立脚本 + 清单兜底 | 要维护四份脚本 | 规则清晰度无法自证，必须有机检 |
| 项数口径 | 文档数字由脚本回算并把关打包 | 每次改规则都要同步三份文档 | 「文档说 127、实际 128」已真实发生两次；让人肉记数字必然出错 |

## 9. 已知局限

1. **不能保证知识绝对正确。** 四关只能让错误便宜地被发现，不能消除。
2. **第一性原理依赖领域性质。** 有些领域（如调机顺序、公差等级）追不到第一性原理，只能标「待补」。
3. **图谱质量受调研深度限制。** 调研只到目录级，图谱的「前提假设」也只能到目录级。
4. **`concept_cards` 与 `concepts` 靠断言同步，不是结构保证。** 理论上能绕过，只是审计会抓。
5. **盲测覆盖不到长会话。** 真实使用可能在第 20 课才暴露问题，盲测只能模拟前几步。
6. **弹窗依赖宿主能力。** 无 `show_widget` 退化纯文本，无 `sendPrompt` 退化为提示手抄。
7. **「图好不好看、可不可读」规定不了。** 手册能规定「每个概念要有 2D/3D」，规定不了
   「标签不能压线、字号在 200px 宽的卡片里能不能读」。盲测执行者改稿 7 次，其中 6 次是
   坐标重叠/贴边/文字糊成一团——这些都是靠截图自查发现的，不是靠读手册。
   推论：**生成类产物必须配可执行的校验脚本 + 人工过一眼图**，`grep -c` 只能证明「有图」，证明不了「图能用」。

8. **`dist/` 里的旧版本包不是历史快照。** `build.py` 每次都从「当前源码 + 当前文档」重新打包，
   所以 `learn-system-v0.9.4.zip` 里装的其实是**现在的内容**，只有版本号字符串不同。
   要拿到真正的历史版本，需要从 git tag 重新构建——**当前没做这件事**。
   影响：不能靠 dist 里的旧包回退或做版本对比；已在 v0.8.2 的 release 说明里加了警告。

## 10. 构建与版本

```bash
python build.py              # 递增 patch → 同步三份文档版本号 → 部署到已装副本 → 打 zip
python build.py --bump minor
python build.py --no-bump    # 只打包
python learn-system-audit.py # 校验，退出码非 0 即 FAIL
```

`VERSION` 是版本号唯一真源；`build.py` 递增后把新版本号正则写回 README、用户手册、技术手册。

**部署不是可选项**：仓库副本（`skill/learn-system/`）与已安装副本
（`~/.workbuddy/skills/learn-system/`）是两个独立文件树，只改仓库不部署 = 跑的还是旧副本。
`build.py` 打包前自动 `deploy()`；审计 U 段逐文件比对，不一致直接 FAIL。

发布产物：`dist/learn-system-vX.Y.Z.zip`（含 `learn-system/` + `docs/` + `VERSION`）。
